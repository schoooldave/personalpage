# 《数据不等于价值》文章重构设计

## 目标

将 `/notes` 从“项目过程加行业观点”的混合页面，重构为一篇以 FMCG 数据数字化行业认知为主的文章。项目经历只作为观点来源和有限验证，不承担正文主叙事。

## 标题与核心问题

主标题：`数据不等于价值`

引导问题：`为什么企业获得了更多渠道数据，却没有同步获得更真实的经营判断？`

核心判断：FMCG 数据跨越总部、销售、经销商与终端产生。总部获得渠道可见性和管理依据，销售与经销商承担采集、推动、信息暴露和执行配合成本。当数据贡献成本与数据价值分属于不同角色，采集容易从业务协作变成管理任务，最终影响数据的持续性、真实性与可用性。

## 内容结构

### 1. 认知冲突

先提出“更多数据为什么没有带来更多价值”，不先展示五阶段框架，也不介绍作者和项目背景。

### 2. 角色不对称

用总部、销售、经销商三个角色说明同一份数据对应不同目标、收益与成本：

- 总部获得可见性和管理依据。
- 销售承担推动、解释、培训和跟进成本。
- 经销商承担数据贡献成本与合作风险。

### 3. 三个关键断点

正文只展开三个高价值问题：

1. 为什么优化入口仍然解决不了持续采集：稳定采集首先取决于价值交换能否成立。
2. 为什么数据更多仍然无法支持管理：数据可靠需要持续治理，数据可用需要明确决策问题。
3. 为什么形成判断仍然没有发生改变：系统能力必须被角色、流程和管理机制接住。

### 4. 完整价值链

在文章后段集中展示：`稳定采集 → 数据可靠 → 形成判断 → 推动行动 → 结果反馈`。价值链用于总结前文，不作为五个独立大章节。

### 5. 行业结论

结论聚焦“修复从贡献数据到改变行动之间的断点”。不使用“阶段性理解”“我逐渐意识到”等自我解释，不把文章写成个人复盘。

## 项目证据的作用

每个关键断点旁保留一处简短的“真实观察”：

- DMS 调研：经销商分享意愿取决于合作方式、支持政策、执行负担和价值说明。
- 数据治理：重复数据、异常上传、周报、月报和使用统计说明可靠性与决策场景需要持续建设。
- 有限验证：600+ 重点经销商上线、上传率约 70%→90%，用于验证流程运行和系统采用。

证据通过现有圆弧门户进入独立深色空间，不在正文中展开完整项目过程。明确声明项目数据不能直接归因成销售增长。

## 页面设计

- 保留工作区的浅色纸张、黑色衬线标题和橙色强调色。
- 首屏只呈现标题、问题和核心矛盾，不放“阶段性理解”标签。
- 核心判断使用深色满宽区块，制造从问题到洞察的视觉转折。
- 三角色使用横向关系卡，不做传统产品卡片样式。
- 三个正文段落采用“编号 + 主文 + 真实观察”的三栏结构。
- 价值链放在文章后段，以单条连续轨道呈现。
- 结尾使用深色总结区，形成明确收束。

## 动效

- 首屏文字只做轻微滚动进入，不使用持续漂浮或装饰动画。
- 三角色模块随滚动依次显露，强调角色关系。
- 价值链在进入视口时从左到右连接。
- “真实观察”入口继续使用已实现的圆弧证据门户。
- 尊重 `prefers-reduced-motion`，关闭位移与圆弧过渡时仍保持完整可读性。

## 响应式

- 桌面端保留三角色横排和正文三栏。
- 移动端三角色改为纵向，正文改为编号与正文两栏，真实观察放到正文下方。
- 不允许横向溢出；正文行宽保持适合阅读。

## 边界

- 本次只重构第一篇文章及其页面。
- 不新增案例，不重写 DMS 详情页，不扩展第二、第三篇文章。
- 不引入新动画依赖。
- 不增加为了视觉高度而重复的正文内容。

## 验收标准

- 首屏能在十秒内说明文章讨论的行业问题。
- 阅读后能够形成“数据贡献成本与数据价值分属于不同角色”的明确认知。
- 正文围绕三个断点展开，不退化为五阶段说明书或项目复盘。
- 项目证据不抢占正文主线，且公开边界清楚。
- 圆弧证据入口、Escape 关闭、焦点恢复和 reduced-motion 保持可用。
- `/notes` 返回 HTTP 200，定向测试和 lint 通过。
